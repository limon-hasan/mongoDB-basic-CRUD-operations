# This is NOT the Next.js you know

This version has breaking changes — APIs, conventions, and file structure may all differ from your training data. Read the relevant guide in `node_modules/next/dist/docs/` (resolved from this file's directory; in monorepos the `next` package may not be visible from the repo root) before writing any code. Heed deprecation notices.

This block is written and re-added by `next dev` — verify at `node_modules/next/dist/server/lib/generate-agent-files.js`. Removing it from a diff only re-creates the uncommitted change; committing it with your work keeps the tree clean.

## Commands

- `npm run dev` — dev server on :3000.
- `npm run lint` (ESLint flat config) and `npm run typecheck` (`tsc --noEmit`) — the only checks; there is no test suite, so don't invent `npm test`.
- `npm run build` — production build. The user routes are dynamic, so the build itself doesn't need the API.
- `npm run format` rewrites every `.ts`/`.tsx` file; use `npx prettier --write <path>` for focused changes. Prettier is configured for no semicolons, double quotes, LF, and Tailwind class sorting.

## Backend dependency

- Every user page/action calls the API directly through `API_BASE_URL` in `lib/api.ts`, which reads `NEXT_PUBLIC_API_URL` and falls back to `http://localhost:5000`. There are no API routes or server actions. `app/page.tsx` and `app/error.tsx` render `API_DISPLAY_HOST` from the same module.
- The API is the sibling package in this repo at `../simple-crud-server`. Start it with `npm run dev` (watch) or `npm start`. It needs a gitignored `.env` with `DB_USER`/`DB_PASS` (see `.env.example`) and serves Mongo database `simpleCrudDB`, collection `users`.
- Endpoints: `GET/POST /users`, `GET/PATCH/DELETE /users/:id`. Create checks `acknowledged`; delete checks `deletedCount`; both dialogs handle `404` for records that disappeared.
- After mutations the UI calls `router.refresh()` (create redirects to `/users`); keep that pattern rather than adding `revalidatePath` unless converting to server actions.

## Next.js 16 specifics

- Consult `node_modules/next/dist/docs/` before reaching for an API; this version differs from most training data. `params`/`searchParams` are Promises — see `app/users/[userId]/page.tsx`.
- **The user routes are explicitly dynamic.** `/users` uses `export const dynamic = "force-dynamic"` and both user pages fetch with `cache: "no-store"`, so CRUD changes appear without a rebuild. If you remove that config, `next build` will execute the fetch and bake the current rows into static HTML (the old behavior).
- The managed `nextjs-agent-rules` block above is regenerated by `next dev`. Keep it and commit it; deleting it only recreates a dirty diff.

## UI conventions

- shadcn is configured with `"style": "base-nova"` and **`@base-ui/react`, not Radix**. Compose triggers with the `render` prop (`<DialogTrigger render={<Button />} />`); there is no `asChild`. Don't paste Radix-based shadcn examples.
- Add primitives with `npx shadcn@latest add <name>`; they land in `@/components/ui`. Keep app-specific components at `components/` root.
- Shared app UI: `site-header.tsx` (nav/theme), `page-header.tsx`, `user-avatar.tsx`, `empty-state.tsx`, `delete-user-button.tsx`. The `User` record type is in `lib/types.ts`.
- `cn` comes from the `cn` package (`lib/utils.ts` only re-exports it). Don't add `clsx`/`tailwind-merge`. When styling a `<Link>` as a button, use `cn(buttonVariants(...))`; the raw cva string contains conflicting border classes and outline links lose their border.
- Tailwind v4: no `tailwind.config.*`; tokens and base styles live in `app/globals.css` (referenced by both `components.json` and Prettier).
- `@/*` maps to the repo root, so `app/`, `components/`, `hooks/`, and `lib/` sit at the top level.
- Theming uses `next-themes` with a class attribute; pressing `d` toggles dark mode (ignored while typing) via `components/theme-provider.tsx`.
